### 1.2 目录职责边界规则

| 目录 | 放什么 | 禁止放什么 |
|---|---|---|
| `src/api/` | 接口调用函数，只做 HTTP 请求 | 业务逻辑、UI 操作、路由跳转 |
| `src/components/` | 跨角色复用的 UI 组件 | 直接调用 API、包含具体业务逻辑 |
| `src/composables/` | 跨组件复用的逻辑（状态+副作用）| UI 模板代码 |
| `src/layouts/` | 布局骨架（导航/菜单/页头）| 业务功能页面 |
| `src/views/` | 具体业务页面 | 被多处复用的 UI 片段（提取为 components）|
| `src/stores/` | 需跨组件共享的状态 | 单个组件私有状态（用 `ref` 即可）|
| `src/types/` | TypeScript 接口/类型/枚举 | 任何运行时代码 |
| `src/utils/` | 纯函数工具（无副作用）| 有状态逻辑（用 composables）|

## 二、页面路由设计

### 2.1 路由总体结构

```
/                       → 重定向至登录页（未登录）或角色首页（已登录）
/login                  → 登录页（公开）
/403                    → 无权限页（公开）
/404                    → 404 页面（公开）

/admin/                 → AdminLayout（SCHOOL_ADMIN 角色）
/point/                 → PointLayout（POINT_ADMIN 角色）
/teacher/               → TeacherLayout（TEACHER 角色）
/assist/                → AssistLayout（ASSISTANT 角色）
/student/               → StudentLayout（STUDENT 角色）
```

### 2.2 路由 meta 字段规范

**所有路由必须声明以下 meta 字段：**

```typescript
// src/router/types.ts
export interface RouteMeta {
  title: string              // 页面标题（显示在浏览器标签/面包屑）
  requiresAuth: boolean      // 是否需要登录
  roles?: UserType[]         // 允许访问的角色列表（空数组 = 任意已登录）
  permissions?: string[]     // 所需权限编码（AND 关系，全部满足才可访问）
  icon?: string              // 菜单图标（Element Plus 图标名）
  hideInMenu?: boolean       // 是否隐藏在侧边栏菜单（详情页等）
  keepAlive?: boolean        // 是否缓存组件（列表页建议 true，详情页 false）
  breadcrumb?: BreadcrumbItem[]  // 面包屑配置（可选，默认从路由层级推导）
  activeMenu?: string        // 当前路由激活的菜单项路径（详情页时高亮所属列表）
}

// src/types/enums.ts（唯一权威来源）
export enum UserType {
  SCHOOL_ADMIN = 'SCHOOL_ADMIN',
  POINT_ADMIN  = 'POINT_ADMIN',
  TEACHER      = 'TEACHER',
  ASSISTANT    = 'ASSISTANT',
  STUDENT      = 'STUDENT',
}
```

## 三、组件层级划分

### 3.1 四级组件体系

```
Level 1 — 页面组件（Views）
    └── Level 2 — 业务组件（Business Components）
              └── Level 3 — 公共组件（Common Components）
                        └── Level 4 — 基础/UI 组件（Element Plus）
```

| 层级 | 位置 | 特征 | 可调用 API？ |
|---|---|---|---|
| 页面组件 | `src/views/` | 与路由 1:1 对应，组织其他组件 | ✅ 直接调用 api/ |
| 业务组件 | `src/views/<role>/<module>/components/` | 属于某个页面的子组件，不跨角色复用 | ✅ 可调用 api/ |
| 公共组件 | `src/components/` | 跨角色复用，不含具体业务逻辑 | ❌ 通过 props/emit/composable |
| Element Plus | 直接引入 | UI 基础控件 | ❌ |

### 3.2 业务组件放置规则

```
src/views/admin/user/
├── StudentListView.vue               # 页面组件（路由入口）
└── components/                       # 该页面私有的业务组件
    ├── StudentTable.vue              # 学生列表表格
    ├── StudentFormDialog.vue         # 新增/编辑弹窗
    ├── ImportResultDrawer.vue        # 导入结果抽屉
    └── BatchAssignDialog.vue         # 批量分配批次弹窗
```

**规则：**
1. 某个组件**只被一个页面使用** → 放在该页面目录下的 `components/` 子目录
2. 某个组件**被同角色多个页面使用** → 放在 `src/views/<role>/components/`（同角色共享）
3. 某个组件**被多个角色使用** → 放在 `src/components/`（全局公共）

## 四、状态管理约定

### 4.1 Store 设计原则

| 原则 | 说明 |
|---|---|
| **单一职责** | 每个 Store 只负责一个业务域 |
| **最小化全局状态** | 只有真正需要跨组件共享的状态才放 Store，单组件私有状态用 `ref` |
| **禁止 Store 互调** | Store 之间禁止直接引用（防止循环依赖），组件层负责协调多个 Store |
| **命名统一** | 文件名 `<domain>.ts`，导出函数名 `use<Domain>Store` |

### 4.2 各 Store 职责与结构

```typescript
import { authApi } from '@/api/auth'
import type { UserInfo, LoginByPasswordDTO } from '@/types/user'
import { UserType } from '@/types/enums'

    userType:        (state): UserType | null => state.userInfo?.userType ?? null,
    userId:          (state): string    => state.userInfo?.userId ?? '',
    schoolId:        (state): string    => state.userInfo?.schoolId ?? '',
    teachingPointId: (state): string | null => state.userInfo?.teachingPointId ?? null,
    realName:        (state): string    => state.userInfo?.realName ?? '',
    // 角色判断快捷方式
    isSchoolAdmin:   (state): boolean   => state.userInfo?.userType === UserType.SCHOOL_ADMIN,
    isPointAdmin:    (state): boolean   => state.userInfo?.userType === UserType.POINT_ADMIN,
    isTeacher:       (state): boolean   => state.userInfo?.userType === UserType.TEACHER,
    isAssistant:     (state): boolean   => state.userInfo?.userType === UserType.ASSISTANT,
    isStudent:       (state): boolean   => state.userInfo?.userType === UserType.STUDENT,
    // 角色对应的首页路径
    homeRoute: (state): string => {
      const map: Record<UserType, string> = {
        [UserType.SCHOOL_ADMIN]: '/admin/dashboard',
        [UserType.POINT_ADMIN]:  '/point/dashboard',
        [UserType.TEACHER]:      '/teacher/dashboard',
        [UserType.ASSISTANT]:    '/assist/dashboard',
        [UserType.STUDENT]:      '/student/dashboard',
      }
      return state.userInfo ? map[state.userInfo.userType] : '/login'
    },
  },

  actions: {
    setTokens(accessToken: string, refreshToken: string) {
      this.accessToken  = accessToken
      this.refreshToken = refreshToken
    },
    setUserInfo(userInfo: UserInfo) {
      this.userInfo = userInfo
    },
    async loginByPassword(dto: LoginByPasswordDTO) {
      const res = await authApi.loginByPassword(dto)
      this.setTokens(res.data.accessToken, res.data.refreshToken)
      this.setUserInfo(res.data.userInfo)
      // 登录后立即应用角色默认主题（需在文件顶部 import { useAppStore } from './app'）
      useAppStore().applyRoleDefaultTheme(res.data.userInfo.userType)
    },
    async logout() {
      try { await authApi.logout() } catch { /* Token 已失效，忽略错误 */ }
      this.$reset()
    },
    clearAuth() {
      this.$reset()
    },
  },

  // 持久化：Token 和 userInfo 存 localStorage
  persist: {
    key: 'thesis-user',
    storage: localStorage,
    paths: ['accessToken', 'refreshToken', 'userInfo'],
  },
})
```

```typescript
// src/stores/paper.ts
// 学生当前批次论文的节点状态，避免多个页面重复请求
import { defineStore } from 'pinia'
import { paperApi } from '@/api/paper'
import type { PaperFlowVO } from '@/types/paper'

export const usePaperStore = defineStore('paper', {
  state: () => ({
    paperId:      null as string | null,
    paperFlow:    null as PaperFlowVO | null,   // 完整流程节点状态
    loading:      false,
    lastFetched:  0,                            // 上次拉取时间（ms），用于缓存控制
  }),

  getters: {
    currentNode: (state) => state.paperFlow?.currentNode,

    // 判断某节点是否已完成
    isNodeApproved: (state) => (nodeType: string): boolean =>
      state.paperFlow?.nodes.find(n => n.nodeType === nodeType)?.status === 'APPROVED',

    // 判断某节点是否可提交（前置节点已完成且在时间窗口内）
    isNodeSubmittable: (state) => (nodeType: string): boolean => {
      const node = state.paperFlow?.nodes.find(n => n.nodeType === nodeType)
      return node?.submittable === true
    },
  },

  actions: {
    // 拉取论文流程状态（含 5 分钟本地缓存）
    async fetchPaperFlow(force = false) {
      const now = Date.now()
      if (!force && this.paperFlow && now - this.lastFetched < 5 * 60 * 1000) return

      this.loading = true
      try {
        const res = await paperApi.getMyPaperFlow()
        this.paperId   = res.data.paperId
        this.paperFlow = res.data
        this.lastFetched = now
      } finally {
        this.loading = false
      }
    },
    // 提交成功后刷新状态
    invalidate() {
      this.lastFetched = 0
    },
  },

  persist: false,   // 论文状态不持久化（页面刷新重新拉取最新数据）
})
```

```typescript
import type { ImGroup, ImMessage } from '@/types/im'

export const useImStore = defineStore('im', {
  state: () => ({
    groups:         [] as ImGroup[],
    activeGroupId:  null as string | null,
    // 消息以 groupId 为 key 分组存储（最近 100 条）
    messages:       {} as Record<string, ImMessage[]>,
    // 各群组未读数
    unreadCounts:   {} as Record<string, number>,
    wsConnected:    false,
    wsReconnecting: false,
  }),

  getters: {
    activeGroup:    (state) => state.groups.find(g => g.groupId === state.activeGroupId),
    activeMessages: (state) => state.messages[state.activeGroupId ?? ''] ?? [],
    totalUnread:    (state) => Object.values(state.unreadCounts).reduce((a, b) => a + b, 0),
  },

  actions: {
    setGroups(groups: ImGroup[]) { this.groups = groups },
    setActiveGroup(groupId: string) {
      this.activeGroupId = groupId
      this.unreadCounts[groupId] = 0   // 进入群组清零未读
    },
    appendMessage(groupId: string, msg: ImMessage) {
      if (!this.messages[groupId]) this.messages[groupId] = []
      this.messages[groupId].push(msg)
      // 最多保留 100 条（防止内存溢出）
      if (this.messages[groupId].length > 100) {
        this.messages[groupId].shift()
      }
      // 非当前激活群组则增加未读
      if (groupId !== this.activeGroupId) {
        this.unreadCounts[groupId] = (this.unreadCounts[groupId] ?? 0) + 1
      }
    },
    setWsStatus(connected: boolean, reconnecting = false) {
      this.wsConnected    = connected
      this.wsReconnecting = reconnecting
    },
  },

  persist: false,
})
```

### 5.1 路由守卫（三道关卡）

```typescript
// src/router/guards.ts
import type { Router } from 'vue-router'
import { useUserStore } from '@/stores/user'
import { usePermissionStore } from '@/stores/permission'
import type { UserType } from '@/types/enums'

export function setupRouterGuards(router: Router) {

  router.beforeEach(async (to, from, next) => {
    const userStore       = useUserStore()
    const permissionStore = usePermissionStore()

    // ─── 关卡 1：公开路由直接放行 ──────────────────────────
    if (!to.meta.requiresAuth) {
      // 已登录用户访问登录页，重定向至首页
      if (to.path === '/login' && userStore.isLoggedIn) {
        return next(userStore.homeRoute)
      }
      return next()
    }

    // ─── 关卡 2：未登录跳转登录页 ──────────────────────────
    if (!userStore.isLoggedIn) {
      return next({
        path: '/login',
        query: { redirect: to.fullPath },   // 记录目标路径，登录后跳回
      })
    }

    // ─── 关卡 3：角色与权限校验 ────────────────────────────
    const requiredRoles = to.meta.roles as UserType[] | undefined
    const requiredPerms = to.meta.permissions as string[] | undefined

    // 3a. 角色校验
    if (requiredRoles && requiredRoles.length > 0) {
      const userType = userStore.userType
      if (!userType || !requiredRoles.includes(userType)) {
        return next('/403')
      }
    }

    // 3b. 权限点校验（所有权限 AND 关系）
    if (requiredPerms && requiredPerms.length > 0) {
      if (!permissionStore.hasAllPermissions(requiredPerms)) {
        return next('/403')
      }
    }

    next()
  })

  // 路由跳转完成后设置页面标题
  router.afterEach((to) => {
    const title = to.meta.title as string | undefined
    document.title = title ? `${title} — 宸章论文系统` : '宸章论文系统'
  })
}
```

```typescript
// src/directives/permission.ts
import type { App, DirectiveBinding } from 'vue'
import { usePermissionStore } from '@/stores/permission'

// 使用方式：
// v-permission="'paper:review'"              — 需要单个权限
// v-permission="['paper:review', 'paper:annotate']"  — 需要所有权限（AND）
// v-permission.or="['paper:review', 'paper:list']"   — 需要任意一个（OR）

export const permissionDirective = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    applyPermission(el, binding)
  },
  updated(el: HTMLElement, binding: DirectiveBinding) {
    applyPermission(el, binding)
  },
}

function applyPermission(el: HTMLElement, binding: DirectiveBinding) {
  const permissionStore = usePermissionStore()
  const required = Array.isArray(binding.value) ? binding.value : [binding.value]
  const mode     = binding.modifiers.or ? 'OR' : 'AND'

  const hasAccess = mode === 'OR'
    ? permissionStore.hasAnyPermission(required)
    : permissionStore.hasAllPermissions(required)

  if (!hasAccess) {
    // 隐藏元素（保留 DOM 结构，防止布局抖动）
    el.style.display = 'none'
    // 或直接移除：el.parentNode?.removeChild(el)
  } else {
    el.style.display = ''
  }
}

// 注册到 Vue 应用
export function setupDirectives(app: App) {
  app.directive('permission', permissionDirective)
}
```

### 7.6 useWebSocket 组合式函数

```typescript
// src/composables/useWebSocket.ts
// WebSocket 连接管理（IM 群聊 + 答辩实时信令共用此 composable）
import { ref, onUnmounted } from 'vue'
import { useImStore } from '@/stores/im'

export function useWebSocket() {
  const imStore    = useImStore()
  const ws         = ref<WebSocket | null>(null)
  const connecting = ref(false)

  const connect = (token: string) => {
    if (ws.value?.readyState === WebSocket.OPEN) return
    connecting.value = true
    ws.value = new WebSocket(`${import.meta.env.VITE_WS_URL}?token=${token}`)

    ws.value.onopen    = () => { connecting.value = false; imStore.setWsStatus(true) }
    ws.value.onclose   = () => { imStore.setWsStatus(false); scheduleReconnect(token) }
    ws.value.onerror   = () => imStore.setWsStatus(false, true)
    ws.value.onmessage = (e) => {
      const msg = JSON.parse(e.data)
      imStore.appendMessage(msg.groupId, msg)
    }
  }

  let reconnectTimer: ReturnType<typeof setTimeout>
  const scheduleReconnect = (token: string) => {
    reconnectTimer = setTimeout(() => connect(token), 3000)
  }

  const disconnect = () => {
    clearTimeout(reconnectTimer)
    ws.value?.close()
    ws.value = null
    imStore.setWsStatus(false)
  }

  const send = (payload: object) => {
    if (ws.value?.readyState === WebSocket.OPEN) {
      ws.value.send(JSON.stringify(payload))
    }
  }

  onUnmounted(disconnect)

  return { connect, disconnect, send, connecting }
}
```

```typescript
// AI 能力统一封装，供 AiPanel / RichEditor 浮动按钮 / AiFab 三种入口共用
import { ref } from 'vue'
import { aiApi } from '@/api/ai'
import type { AiStreamParams } from '@/types/ai'

export function useAI() {
  const generating = ref(false)
  const result     = ref('')
  const error      = ref<string | null>(null)

  // 流式生成（SSE）— 大纲推荐、论文摘要等实时展示场景
  const generateStream = async (params: AiStreamParams) => {
    generating.value = true
    result.value     = ''
    error.value      = null
    try {
      const es = await aiApi.streamGenerate(params)
      es.onmessage = (e) => {
        if (e.data === '[DONE]') { generating.value = false; es.close(); return }
        result.value += JSON.parse(e.data).delta ?? ''
      }
      es.onerror = () => {
        generating.value = false
        error.value = 'AI 服务暂时不可用，请稍后重试'
        es.close()
      }
    } catch {
      generating.value = false
      error.value = 'AI 请求失败'
    }
  }

  // 非流式调用（一次性返回）— 论文校对、参考文献推荐等无需实时展示的场景
  const generate = async (params: AiStreamParams): Promise<string> => {
    generating.value = true
    error.value = null
    try {
      const res = await aiApi.generate(params)
      result.value = res.data.content
      return result.value
    } catch {
      error.value = 'AI 请求失败'
      return ''
    } finally {
      generating.value = false
    }
  }

  return { generating, result, error, generateStream, generate }
}
```

### 9.3 组件开发前置检查

新建任何组件前，先在以下清单确认：

```
1. src/components/ 中是否已有相似功能的组件？
   → 若有：复用或扩展现有组件，禁止重复实现
   → 若无：评估是否需要提取为公共组件

2. 该组件是否需要跨角色复用？
   → 是：放 src/components/，定义 types.ts，告知所有人
   → 否：放对应 views/<role>/<module>/components/

3. 组件命名是否与现有组件冲突？
   → 在 src/components/ 和各 views/ 的 components/ 搜索

4. Props 是否覆盖了所有使用场景？
   → 与即将使用该组件的页面开发者确认接口设计
```

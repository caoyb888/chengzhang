## 二、测试用例设计策略

### 2.1 设计原则

1. **风险优先**：P0 功能（多导师管理、IM群组、在线答辩、批注评分、大纲推荐）每个至少 20 条用例，覆盖正向/异常/边界三类场景
2. **等价类 + 边界值**：对所有有范围限制的输入（字数/分值/时间窗口）设计边界值用例
3. **状态机覆盖**：论文流程状态机（NOT_STARTED → PENDING → SUBMITTED → REVIEWING → APPROVED/REJECTED）每条跳转路径均覆盖
4. **并发场景**：选题去重、用户批量导入等高并发场景必须设计竞态条件用例
5. **数据权限矩阵**：五种角色 × 关键资源（论文/批次/统计/消息）构成 5×5 权限矩阵，逐格验证

### 2.2 功能模块用例设计策略

#### 2.2.1 认证与权限模块（对应 F-001～F-005、F-011）

**等价类划分：**

| 类别 | 有效等价类 | 无效等价类 |
|---|---|---|
| 账号密码登录 | 正确用户名 + 正确密码 | 用户名不存在 / 密码错误 / 账号已停用 / 账号已锁定 |
| 短信验证码登录 | 正确手机号 + 正确验证码（5min 内）| 验证码过期 / 错误验证码 / 60s 内重复发送 |
| Token 鉴权 | 有效 Bearer Token | 无 Token / Token 过期（401）/ 权限不足（403）|
| 数据权限 | SCHOOL_ADMIN 查全校 / POINT_ADMIN 查本点 | POINT_ADMIN 越权查他点数据 |

**关键用例：**

| 用例编号 | 用例名称 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|---|
| TC-AUTH-001 | 密码登录-正向 | 账号状态 ACTIVE | POST /auth/login，正确用户名密码 | code=200，返回有效 token |
| TC-AUTH-002 | 密码连续错误锁定 | 账号状态 ACTIVE | 连续 5 次错误密码 | 第5次返回 code=1003（锁定提示含分钟数）|
| TC-AUTH-003 | Token 刷新 | Access Token 已过期，Refresh Token 有效 | POST /auth/token/refresh | 返回新 Access Token，原请求重放成功 |
| TC-AUTH-004 | Refresh Token 过期 | 两个 Token 均过期 | POST /auth/token/refresh | code=4010，前端跳转登录页 |
| TC-AUTH-005 | 多端互踢 | 同账号 WEB 端已登录 | 同一账号再次 WEB 登录 | 旧 Token 失效（返回 4011），新 Token 有效 |
| TC-AUTH-006 | POINT_ADMIN 越权 | POINT_ADMIN 账号 | 查询其他教学点学生列表 | 返回 code=403 或空数据集（数据权限隔离）|
| TC-AUTH-007 | 权限缓存失效刷新 | 用户已登录，角色权限被管理员修改 | 等待 TTL 1h 或强制刷新 | 权限变更在缓存过期后生效 |

#### 2.2.2 论文流程引擎（对应 F-007～F-010、F-032～F-037）

**状态机完整路径矩阵：**

```
正向路径（顺序流转）：
  PENDING → 学生提交 → SUBMITTED → 教师审核中 → REVIEWING
  → Level-1 通过 → Level-2 审核中 → ... → 末级通过 → APPROVED
  → 触发下一节点 PENDING（强制顺序节点）

异常路径（驳回/退回）：
  REVIEWING → 任意 Level REJECTED → 退回学生 → PENDING（allow_reject=1）
  REVIEWING → 末级 REJECTED + allow_reject=0 → REJECTED（终态）

边界路径：
  时间窗口边界：在 start_time 前1秒提交 → 2001
  时间窗口边界：在 end_time 后1秒提交（无逾期通道）→ 2001
  时间窗口边界：有逾期通道且在 expire_at 内提交 → 允许
  前置节点未完成：跳过必选前置节点提交 → 2002
  评语最低字数：评语 min_comment_length-1 字 → 2005
  评语最低字数：评语 = min_comment_length 字 → 通过
```

**关键用例：**

| 用例编号 | 用例名称 | 设计方法 | 预期结果 |
|---|---|---|---|
| TC-FLOW-001 | 三级多导师顺序审核全链路 | 场景法（P0 核心场景） | Level1→Level2→Level3 逐级 APPROVED，节点最终 APPROVED |
| TC-FLOW-002 | Level2 驳回退回学生 | 状态机异常路径 | allow_reject=1 时学生可重新提交；=0 时节点 REJECTED |
| TC-FLOW-003 | 强制顺序校验 | 边界值（sort_order） | 跳过 sort_order=1 的必选节点提交 sort_order=2 → code=2002 |
| TC-FLOW-004 | 时间窗口边界 | 边界值 | start_time 前1秒提交 → 2001；整点后1秒提交 → 200 |
| TC-FLOW-005 | 逾期通道授权提交 | 场景法 | 教师开启逾期通道后，学生在 expire_at 内提交成功 |
| TC-FLOW-006 | 状态变更事务原子性 | 故障注入（模拟 DB 失败）| 状态变更中途 DB 异常，状态回滚，操作日志无记录 |
| TC-FLOW-007 | 评语字数边界 | 边界值 | min_comment_length=50，提交49字 → 2005；50字 → 200 |
| TC-FLOW-008 | 论文缓存一致性 | 场景法 | 状态变更后 paper:status:{paperId} 缓存被删除，下次查询从 DB 读取 |

### 5.3 性能测试基准指标汇总

#### 响应时间指标

|---|---|---|---|---|---|

| AI 流式接口（首 token）| ≤ 1s | ≤ 2s | ≤ 3s | ≤ 5s | 10s |

| 文件上传（≤10MB，不含传输）| ≤ 100ms | ≤ 200ms | ≤ 500ms | ≤ 1s | 2s |

#### 吞吐量指标

|---|---|---|

### 5.4 性能问题应急处理

**Day 6 摸底测试发现性能不达标时：**

| 问题类型 | 排查方向 | 应急措施 |
|---|---|---|
| 数据库慢查询（>100ms）| SkyWalking 链路 + MySQL slow log | 加索引（当日修复）|
| N+1 查询 | SkyWalking DB Call 数量异常 | 改为批量查询（当日修复）|
| 缓存命中率低 | Redis Monitor / Grafana | 扩大 TTL 或增加缓存覆盖范围 |
| JVM GC 频繁 | JVM GC 日志 / Grafana JVM 面板 | 调整堆大小或优化对象分配 |
| 连接池耗尽 | MySQL 连接数监控 | 增加连接池 max-size 或增加副本 |
| 接口热点竞争 | Redis KEY 分布 / DB 行级锁 | 分布式锁优化或本地缓存降级 |

**未达标时降级策略（Day 9-10 压测期间）：**

```
P99 > 500ms 但 ≤ 1s：标记 WARN，继续压测，记录缺陷
P99 > 1s：暂停压测，立即优化，优化后重跑
错误率 > 0.1%：暂停压测，分析错误日志，定位根因
```

## 七、缺陷管理规范

### 7.1 缺陷优先级定义

| 优先级 | 定义 | 示例 | 修复时限 |
|---|---|---|---|
| P0（阻断）| 系统崩溃 / P0 演示功能不可用 / 数据丢失 | 论文状态变更后数据不一致；IM 无法发消息 | 当天修复，重测通过才能发布 |
| P1（严重）| 核心功能无法使用 / 安全漏洞 | 批量导入完全失败；越权访问 | 24h 内修复 |
| P2（一般）| 功能部分异常 / 性能不达标 | 某边界条件返回错误码；某接口 P99 超 500ms | Sprint 内修复 |
| P3（轻微）| UI 问题 / 文案错误 / 小概率路径 | 按钮文字不一致；错误提示措辞 | 下个 Sprint 修复或记录 |

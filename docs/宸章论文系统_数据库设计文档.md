## 一、数据库总体规划

### 1.1 分库实例规划

系统按功能域分为 4 个 MySQL 实例，每个实例采用「1 主 2 从」高可用架构：

| 实例标识 | 包含数据库 | 归属服务 | 主要特点 |
|---|---|---|---|
| db-core | thesis_auth、thesis_user | thesis-auth、thesis-user | 高频读写（登录/权限），用户体量大 |
| db-paper | thesis_paper、thesis_template | thesis-paper、thesis-template | 核心业务，数据量最大，写多读多 |
| db-im | thesis_im | thesis-im、thesis-defense | 消息量极大，需归档策略 |
| db-biz | thesis_statistics、thesis_notify | thesis-statistics、thesis-notify | 统计预计算，批量写为主 |

### 1.2 全局规范

```sql
-- 全局默认配置（my.cnf）
[mysqld]
character-set-server    = utf8mb4
collation-server        = utf8mb4_unicode_ci
default-storage-engine  = InnoDB
innodb_buffer_pool_size = 32G      -- 按实例配置
max_connections         = 2000
slow_query_log          = 1
long_query_time         = 0.1      -- 100ms 以上记录慢查询
binlog_format           = ROW
sync_binlog             = 1        -- 主从强一致
innodb_flush_log_at_trx_commit = 1
```

### 1.3 建表公共约定

```sql
-- 1. 所有表必须包含的基础字段（四件套）
`id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID（雪花算法生成）',
`created_at` DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`updated_at` DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP 
             ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间',
`is_deleted` TINYINT(1)      NOT NULL DEFAULT 0 COMMENT '逻辑删除标记（0-正常 1-已删除）',

-- 2. 多租户字段（业务表必须包含）
`school_id`  BIGINT UNSIGNED NOT NULL COMMENT '所属学校ID（多租户隔离）',

-- 3. 所有外键字段命名：<关联表单数>_id
-- 4. 状态字段类型：VARCHAR(32)，存枚举字符串值，不使用数字
-- 5. 金额/分值字段：DECIMAL(10,2)，不使用 FLOAT/DOUBLE
-- 6. 布尔字段：TINYINT(1)，0=否 1=是
-- 7. 长文本字段：TEXT 或 LONGTEXT，独立存表，不与查询表混用
-- 8. JSON 字段：JSON 类型（MySQL 8.0 原生支持），字段名以 _json 结尾
```

### 2.2 核心业务流程 ER 关系说明

| 关系 | 基数 | 说明 |
|---|---|---|
| batch → batch_flow_config | 1:N | 一个批次有多个流程节点配置 |
| batch_flow_config → node_teacher_level | 1:N | 一个节点可配置多个导师层级 |
| user → paper | 1:1（同批次）| 一个学生在一个批次内对应一篇论文 |
| paper → paper_node_status | 1:N | 一篇论文有多个节点状态记录 |
| paper → paper_submit_record | 1:N | 一篇论文在同一节点可多次提交 |
| paper → paper_review_record | 1:N | 一篇论文在同一节点可被多位教师审核 |
| user(teacher) ← teaching_relationship → user(student) | N:M | 师生指导关系多对多 |
| im_group → im_message | 1:N | 一个群组包含多条消息 |
| defense_group → defense_group_member | 1:N | 一个答辩组有多个成员 |

### 3.1 thesis_auth — 认证库

**用途：** 存储登录会话、刷新令牌、OAuth 授权信息，高频读写，与用户库分离以减少锁竞争。

```sql
CREATE DATABASE thesis_auth
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE thesis_auth;
```

#### 表 auth_refresh_token — 刷新令牌表

```sql
CREATE TABLE auth_refresh_token (
  `id`            BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `user_id`       BIGINT UNSIGNED  NOT NULL COMMENT '用户ID，关联 thesis_user.user.id',
  `school_id`     BIGINT UNSIGNED  NOT NULL COMMENT '所属学校ID（多租户隔离）',
  `token_value`   VARCHAR(512)     NOT NULL COMMENT '刷新令牌值（UUID v4，存储哈希值）',
  `client_type`   VARCHAR(32)      NOT NULL DEFAULT 'WEB' COMMENT '客户端类型（WEB / WECHAT）',
  `device_info`   VARCHAR(256)     NULL     COMMENT '设备信息（UA 摘要，用于异地登录检测）',
  `ip_address`    VARCHAR(64)      NULL     COMMENT '颁发时的IP地址',
  `expire_at`     DATETIME         NOT NULL COMMENT '令牌过期时间',
  `is_revoked`    TINYINT(1)       NOT NULL DEFAULT 0 COMMENT '是否已吊销（0-有效 1-已吊销）',
  `created_at`    DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`    DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP
                  ON UPDATE CURRENT_TIMESTAMP COMMENT '最后更新时间',
  `is_deleted`    TINYINT(1)       NOT NULL DEFAULT 0 COMMENT '逻辑删除（0-正常 1-已删除）',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_token_value` (`token_value`(128))  COMMENT '令牌唯一索引（前128字符）',
  KEY `idx_user_client` (`user_id`, `client_type`, `is_revoked`) COMMENT '按用户和客户端类型查询有效令牌',
  KEY `idx_expire_at` (`expire_at`) COMMENT '过期清理任务索引'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='刷新令牌表：存储 Sa-Token 长期令牌，支持多端登录和强制下线';
```

```sql
CREATE TABLE user (
  `id`                BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '主键ID（雪花算法，全局唯一）',

  `teacher_no`        VARCHAR(32)      NULL     COMMENT '工号（教师专用，学校内唯一）',
```

## 四、索引策略

### 4.1 索引设计原则

| 原则 | 说明 |
|---|---|
| 多租户前缀 | 凡查询条件含 `school_id` 的场景，联合索引必须以 `school_id` 开头 |
| 最左前缀 | 联合索引字段顺序：区分度高的放左边，等值查询字段优先于范围查询字段 |
| 覆盖索引 | 高频列表查询尽量做到索引覆盖（无需回表），含 `is_deleted` 避免回表 |
| 数量控制 | 单表索引数 ≤ 8 个（含主键），优先复合索引，避免冗余单列索引 |
| 区分度要求 | 区分度 < 10% 的字段（如 `is_deleted`）不单独建索引，作为复合索引末位字段 |
| 禁止前缀模糊 | 禁止 `LIKE '%xxx'`，允许 `LIKE 'xxx%'` |

### 4.2 高频查询索引分析

#### 查询场景 1：管理端查询批次论文列表（最高频）

```sql

EXPLAIN
SELECT id, student_id, overall_status, word_count
FROM paper
WHERE school_id = 1 AND batch_id = 100 AND overall_status = 'IN_PROGRESS'
AND is_deleted = 0
LIMIT 20 OFFSET 0;
```

## 五、分区策略

### 5.1 分区设计目标

| 目标 | 说明 |
|---|---|
| 历史消息管理 | im_message 按月分区，方便归档 1 年前数据 |
| 日志清理效率 | auth_login_log 按月分区，清理历史日志只需 DROP PARTITION |
| 大表查询性能 | paper_submit_record 按批次年份分区，减少扫描范围 |

```sql
  PARTITION p2024_09 VALUES LESS THAN ('2024-10-01 00:00:00'),
```

### 5.6 分区注意事项

```sql
-- 1. 分区表的唯一键/主键必须包含分区列
-- im_message 的 PRIMARY KEY (id) 需改为 PRIMARY KEY (id, created_at)
-- 或使用 KEY (id) + 分区列，MySQL 8.0 允许此格式
```

```sql
             COMMENT '评语字数（冗余字段，由应用层写入时计算填充，用于统计和页面展示，无需每次COUNT(content)）',

-- 业务规则重要字段
`topic_hash` VARCHAR(64) NOT NULL
             COMMENT '选题哈希值（MD5(batch_id+title.trim())，用于选题去重唯一约束，配合Redisson分布式锁双重保障）',

`min_comment_length` INT NOT NULL DEFAULT 0
             COMMENT '教师评语最低字数（招标要求▲：强制最低字数限制，0=不限制，后端Service层强制校验，前端仅提示）',

-- 逻辑删除标准字段
`is_deleted` TINYINT(1) NOT NULL DEFAULT 0
             COMMENT '逻辑删除标记（0-正常 1-已删除，所有DELETE操作均更新此字段，禁止物理删除）',
```

## 七、数据归档与备份策略

### 7.1 备份计划

| 备份类型 | 频率 | 保留时长 | 存储位置 | 方式 |
|---|---|---|---|---|
| 全量备份 | 每日 00:00 | 30 天 | 主可用区 + 异地 OSS | mysqldump + 压缩加密 |
| 增量备份（binlog）| 每小时 | 7 天 | 异地 OSS | mysqlbinlog 同步 |
| 跨可用区实时同步 | 实时 | — | 从库（异可用区）| 半同步主从复制 |
| 批次数据转存 | 每批次结束后 | 永久（学校自管）| 学校指定存储 | 专项导出脚本 |

### 7.2 批次结束数据转存规范

```sql
-- 每批次论文结束后，生成该批次全量导出包移交学校

-- 导出内容：
-- 1. 批次相关数据（SQL Dump）：
--    batch, batch_flow_config, student_batch, teaching_relationship
--    paper, paper_node_status, paper_submit_record, paper_review_record
--    paper_annotation, paper_score, paper_topic, paper_outline, paper_content
--    electronic_signature, plagiarism_check_record, ideology_scan_record
--    ai_preliminary_review, paper_operation_log

-- 2. 批次相关文件（OSS 打包）：
--    论文提交文件、查重报告、答辩录像、评分导出等

-- 导出命令示例：
mysqldump thesis_paper --tables paper paper_node_status paper_submit_record \
  --where="batch_id = {batchId}" \
  --single-transaction --hex-blob \
  | gzip | openssl enc -aes-256-cbc -pass env:EXPORT_KEY \
  > batch_{batchId}_data_{date}.sql.gz.enc

-- 同时提供数据说明文档（表结构 + 字段说明），便于学校自行还原和解读
```

### 7.3 im_message 历史消息归档

```sql
-- im_message 保留策略：在线保留 >= 1 年（招标要求）
-- 超过1年的消息归档至 im_message_archive 冷存储表

-- 归档操作（利用 RANGE 分区交换）：
-- Step 1: 创建归档表（结构相同，无分区）
CREATE TABLE im_message_archive LIKE im_message;
REMOVE PARTITIONING;  -- 归档表不分区

-- Step 2: 交换分区（秒级操作，不锁主表）
ALTER TABLE im_message
  EXCHANGE PARTITION p2024_01
  WITH TABLE im_message_archive_2024_01
  WITHOUT VALIDATION;

-- Step 3: 删除主表对应分区（释放空间）
ALTER TABLE im_message DROP PARTITION p2024_01;

-- 归档表仍可正常查询（管理员查历史记录），只是速度较慢
-- 归档数据同步转存至对象存储（Parquet 格式）用于长期分析
```

### 7.4 灾备恢复流程

```
RTO（恢复时间目标）≤ 4 小时
RPO（恢复点目标）≤ 1 小时

恢复步骤：
  1. 确认故障类型（主库宕机 / 数据误操作 / 机房灾难）
  2. 主库宕机：从库自动提升（MHA/Orchestrator 自动切换，< 30s）
  3. 数据误操作：
     a. 确定误操作时间点
     b. 从最近全量备份恢复至临时实例
     c. 应用 binlog 至误操作时间点前（point-in-time recovery）
     d. 核对数据后，择机切换或选择性恢复
  4. 恢复完成后更新 Nacos 数据源配置，重启受影响服务
```

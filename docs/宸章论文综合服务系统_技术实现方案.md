## 一、项目概述

### 1.1 项目背景

随着高等学历继续教育规模持续扩大，论文指导管理工作面临学生分布广泛、师生协作难度大、过程监管困难、质量难以保证等核心挑战。曲阜师范大学拟采购一套覆盖论文全生命周期的综合服务系统，实现论文写作、指导、审核、查重、答辩等全流程数字化管理，同时引入 AI 能力提升论文质量和管理效率。

本系统命名为 **宸章高等学历继续教育论文综合服务系统**，宸章智启，知新华篇。

### 1.2 建设目标

| 目标维度 | 具体内容 |
|---|---|
| 流程数字化 | 论文写作全流程线上化，消除纸质材料传递，实现可追溯的过程管理 |
| 管理精细化 | 多角色、多权限、多批次、多专业的精细化管理，支持自定义配置 |
| AI 赋能 | 选题推荐、大纲生成、论文校对、摘要生成、意识形态扫描等 AI 功能全面集成 |
| 高并发支撑 | 支持注册用户 ≥ 10 万人，同时在线 ≥ 10,000 人 |
| 安全合规 | 满足山东省教育委员会及学校对毕业论文管理的合规要求 |

### 1.3 项目范围

系统服务五类角色用户：

- **学校管理员**：全局用户管理、论文流程配置、统计报表、资源管理
- **教学点管理员**：教学点内用户管理、论文进度跟踪、统计
- **指导教师**：论文各阶段审核、在线批注评分、即时沟通
- **辅助指导教师**：分段/整篇论文指导、查重报告审核
- **学生**：论文写作全流程操作、AI 辅助工具使用、在线答辩

### 1.4 交付时间与服务期限

- 合同签订之日起 **10 日内**完成系统交付
- 服务期限 **1 年**，提供 7×24 小时运维响应

## 二、需求分析

### 2.1 用户角色与核心诉求

#### 2.1.1 学校管理员

学校管理员是系统最高权限角色，核心诉求包括：

- 灵活配置论文流程，不同批次、不同专业可独立定制
- 对全校论文进度有全局视图，能够按多维度统计分析
- 管控系统内的信息安全（群聊信息审核、意识形态扫描）
- 支持多导师机制，灵活配置各阶段导师权限

#### 2.1.2 教学点管理员

- 管理本教学点学生和辅助教师
- 查看本教学点论文进度统计
- 处理学生电子签名审核

#### 2.1.3 指导教师

- 高效完成选题、大纲、初稿、定稿、终稿各阶段审核
- 在线对论文进行批注和评分，评语有最低字数要求
- 向学生推荐选题和大纲参考
- 处理特殊情况的逾期提交申请

#### 2.1.4 辅助指导教师

- 对学生论文进行分段或整篇指导
- 与学生和指导教师即时沟通

#### 2.1.5 学生

- 系统引导下完成论文全流程写作
- 使用 AI 工具获得选题、大纲、摘要、参考文献等辅助
- 实时了解论文各阶段审核状态
- 参与在线答辩

### 3.3 前端架构设计

前端采用**单页应用（SPA）+ 多角色布局**架构：

- **技术栈**：Vue 3 + TypeScript + Vite + Element Plus
- **状态管理**：Pinia
- **路由**：Vue Router 4，基于角色的动态路由加载
- **多端布局**：学校管理端、教学点管理端、指导教师端、辅助教师端、学生端，各自独立布局组件，同一项目按角色动态渲染

```
前端工程结构：
thesis-web/
├── src/
│   ├── layouts/           # 五套角色布局
│   │   ├── AdminLayout    # 学校管理端

```

### 3.4 数据流设计

以论文提交审核为例，说明核心数据流：

```
学生提交论文
    │
    ▼
thesis-gateway（JWT 校验 + 限流）
    │
    ▼
thesis-paper（接收提交，写入 paper_submit_record）
    │
    ├─► Redis（更新学生论文状态缓存）
    │
    ├─► RocketMQ（发布"论文提交"事件）
    │         │
    │         ├─► thesis-notify（推送审核提醒给教师）
    │         │
    │         └─► thesis-ai（异步触发论文初步评议）
    │
    └─► Elasticsearch（更新论文内容全文索引，用于查重）
```

### 3.5 多租户数据隔离设计

系统以**学校**为租户单位，通过以下机制实现数据隔离：

- 所有核心业务表包含 `school_id` 字段
- MyBatis-Plus 数据权限插件，自动注入 `school_id` 过滤条件
- 教学点管理员额外注入 `teaching_point_id` 过滤条件
- Redis 缓存 Key 前缀包含 `school_id`，防止跨租户缓存污染

## 四、技术选型与架构

### 4.1 技术选型总览

| 层次 | 技术/框架 | 版本 | 选型理由 |
|---|---|---|---|

### 4.2 数据库架构设计

#### 4.2.1 MySQL 高可用架构

```

                    │   应用服务层     │
                    │  ShardingSphere  │
                    │  JDBC（读写分离）│
                    └──────┬──────────┘
                           │

              │            │            │
        ┌─────▼───┐  ┌─────▼───┐  ┌───▼─────┐

        │（写）   │  │（读）   │  │（读）   │
```

### 5.1 用户与权限管理系统

#### 5.1.1 多角色权限体系设计

系统采用 **RBAC（Role-Based Access Control）+ ABAC（Attribute-Based Access Control）** 混合权限模型：

- **RBAC**：按角色分配菜单和按钮级权限
- **ABAC**：数据权限，按学校、教学点等属性自动过滤数据范围

```
权限层级：
菜单权限（页面访问）
  └── 按钮权限（功能操作：增/删/改/查/导入/导出）
        └── 数据权限（数据范围：全校/本教学点/本人）
```

**角色套餐设计**：

| 套餐名称 | 适用角色 | 预置权限范围 |
|---|---|---|
| 学校管理员标准套餐 | SCHOOL_ADMIN | 全部功能 |
| 教学点管理员套餐 | POINT_ADMIN | 本教学点管理功能 |
| 论文指导教师套餐 | TEACHER | 论文审核、批注、统计 |
| 辅助指导教师套餐 | ASSISTANT | 分段指导、整篇指导、查重审核 |
| 标准学生套餐 | STUDENT | 论文写作全流程 |

支持在套餐基础上 **增减单项权限**，实现个性化配置。

#### 5.1.2 用户导入设计

批量导入采用**异步处理**机制，避免阻塞：

```
用户上传 Excel
    │
    ▼
后端接收文件，生成 ImportTask（taskId）
    │
    ▼
立即返回 taskId 给前端
    │
    ▼（异步）
RocketMQ 消费导入任务
    │
    ├── 逐行校验（手机号格式/必填项/重复数据）
    ├── 批量写入数据库（每批 500 条）
    └── 更新任务进度（Redis 存储进度）

前端通过 taskId 轮询进度，完成后展示成功/失败明细
```

**导入 Excel 模板字段定义**：

| 角色 | 必填字段 | 可选字段 |

**流程配置表（batch_flow_config）核心字段**：

**论文状态机**：

```
                  ┌──────────────────────────────┐
                  │         NOT_STARTED           │
                  │       （未到达该节点）          │
                  └──────────────┬───────────────┘
                                 │ 前置节点完成
                  ┌──────────────▼───────────────┐
                  │           PENDING             │
                  │         （待学生提交）          │
                  └──────────────┬───────────────┘
                                 │ 学生提交
                  ┌──────────────▼───────────────┐
              ┌──►│          SUBMITTED            │
              │   │         （已提交待审核）        │

              │                  │ 教师开始审核
              │   ┌──────────────▼───────────────┐

              │   │           （审核中）            │
              │   └───────┬──────────────┬────────┘

              │   ┌───────▼──┐     ┌─────▼────────┐
              │   │ APPROVED │     │   REJECTED   │

              └───────────────────────────┘
```

#### 5.2.2 多导师机制设计

每个流程节点支持配置**多个导师层级**，独立管理权限：

```
批次流程节点
  └── 导师层级配置（node_teacher_level）
        ├── Level 1（第一级指导教师，如专业导师）
        │     ├── 是否允许退回论文
        │     ├── 评审模式（抽检 / 全检）
        │     └── 是否推送评审意见给学生
        └── Level 2（第二级指导教师，如院系导师）

```

**审核顺序**：Level 1 审核通过后，自动流转至 Level 2，依此类推，末级审核通过后，论文节点完成。

#### 5.2.3 电子签名设计

支持两种签名方式，统一存储为图片：

#### 5.5.2 群组管理设计

|---|---|---|
| 批次大群 | 批次创建时自动生成 | 批次内全部学生 + 学校管理员 |

#### 5.5.3 敏感词过滤设计

采用 **Aho-Corasick 算法**实现高性能多模式匹配：

```
消息发送请求
    │
    ▼
加载敏感词库（Redis 缓存，Trie 树结构）
    │
    ▼
AC 自动机匹配
    ├── 无敏感词 → 正常发送
    └── 含敏感词 → 
          ├── 记录违规日志
          ├── 替换为 *** 
          └── 或直接拦截（按管理员配置决定）
```

### 5.6 在线答辩系统

#### 5.6.1 技术方案选型

在线答辩采用 **WebRTC + 云端 MCU**（选用腾讯云实时音视频 TRTC 或声网 Agora），服务端进行媒体处理，解决 NAT 穿透和多方通话质量问题。

#### 5.6.2 答辩组管理设计

```
答辩组（defense_group）
  ├── 基本信息：组名、答辩时间、答辩形式（同步/异步）
  ├── 成员配置
  │     ├── 主持人（1人，拥有管理权限）
  │     ├── 评委教师（多人）
  │     └── 答辩学生（多人）
  └── 权限配置
        ├── 主持人：全员/单人禁言、禁视频、邀请上台、踢出
        ├── 评委：查看屏幕共享、提交评分
        └── 学生：共享屏幕、开启摄像头/麦克风
```

#### 5.6.3 核心功能实现

**多组并行**：每个答辩组是独立的 RTC 房间（roomId），互相完全隔离，理论支持无限并行组数，受云服务并发房间数限制。

**全程自动录像**：
```
答辩开始 → 云端混流录制启动
    ├── 混流布局：支持多种视图模式
    │     ├── 一屏多等分（宫格布局）
    │     ├── 右侧成员列表（主讲大屏 + 右侧缩略图）
    │     └── 顶部成员列表
    ├── 主持人可手动暂停/恢复录制
    └── 答辩结束 → 录像文件自动上传 MinIO → 生成回放链接
```

**屏幕共享**：学生上台后，浏览器调用 `navigator.mediaDevices.getDisplayMedia()` 获取屏幕流，上传至 RTC 房间，评委和主持人实时查看。

**异步答辩**：
```
学生上传答辩视频（MP4/WMV，限制 2GB）
    │
    ▼
视频转码（云端 HLS 格式）
    │
    ▼
评委在答辩截止日前观看视频，在系统内填写评审意见和评分
    │
    ▼
管理员汇总各评委评分，生成答辩结果
```

### 5.9 AI 功能模块详细设计

所有 AI 功能通过 `thesis-ai` 服务统一提供，内部对接大模型 API（支持配置切换 OpenAI、文心一言、通义千问等），实现以下核心能力：

#### 5.9.1 论文选题推荐

```
输入：学生专业、研究方向关键词（可选）
    │
    ▼
① 检索题库（ES 全文搜索 + 专业过滤）
② 调用大模型生成创新选题（Prompt 包含专业背景）
③ 合并候选选题列表
④ 去重过滤：检查 Redis 中已选题目集合，过滤已被选的
```

#### 5.9.3 论文摘要生成

```
Prompt 设计：
  "你是一位学术写作助手。请根据以下论文内容，生成一篇符合学术规范的中文摘要。
   要求：200-400字，包含研究背景、目的、方法、结论四个要素，语言简洁准确。
   论文内容：{论文全文内容}"

摘要翻译：
  生成中文摘要后，调用翻译 API（百度翻译/DeepL）自动生成英文摘要
  或直接 Prompt 大模型同时生成中英文版本
```

#### 5.9.4 论文校对

多维度校对引擎设计：

```
输入：论文文本内容
    │
    ▼
并行调用多个校对子模块：
  ├── 别字/别词检查：接入百度/讯飞文字校对 API
  ├── 语法错误：大模型检测冗余/缺失/乱序
  ├── 标点检查：规则引擎（中文标点误用规则库）
  ├── 成语误用：成语词典比对
  ├── 敏感词/黑名单：Aho-Corasick 匹配
  ├── 数字规范：规则引擎（阿拉伯数字/汉字数字使用规范）
  └── 地名/机构名/职称：NER 实体识别校验
    │
    ▼
汇总校对结果，标注位置（段落号+字符偏移）和修改建议
    │
    ▼
前端高亮显示错误位置，用户逐条确认修改
```

#### 5.9.5 同届查重

```
查重方式：
  ① 同届内部比对（自研）：
     - 论文提交时，提取文本特征（n-gram + MinHash）存入 ES
     - 查重时，计算待查论文与批次内其他论文的 Jaccard 相似度
     - 相似度 > 30% 标记为疑似，高亮重复片段

  ② 接入第三方查重（知网/维普/万方）：
     - 学生在系统内发起查重请求
     - 系统调用第三方 API 上传论文，获取查重报告 URL
     - 自动解析报告，展示相似率和重复来源
     - 生成查重报告 PDF，存储至 MinIO
```

#### 5.9.6 意识形态扫描

```
扫描维度：
  ├── 敏感词匹配：政治敏感词、民族宗教词汇
  ├── 涉政内容：大模型分析，识别特定政治立场表述
  ├── 文化价值观：识别反社会主义价值观表述
  ├── 广告语言：识别商业广告用语
  └── 辱骂歧视：识别针对人群的歧视性语言

输出格式：
  {
    "overallRisk": "LOW/MEDIUM/HIGH",
    "details": [
      {
        "dimension": "涉政内容",
        "risk": "MEDIUM",
        "location": "第3章第2节",
        "content": "...",
        "suggestion": "建议修改为..."
      }
    ]
  }
```

#### 5.9.7 论文初步评议

```
评议流程：
  1. 管理端配置评议标准（参照山东省教委毕业论文要求）
  2. 管理员选择单个或批量学生触发评议

     - 格式规范性
  5. 生成评议报告（Markdown 格式），存入数据库
  6. 管理员查看评议结果，可导出 Excel
```

### 6.1 高性能与高并发设计

#### 6.1.1 并发容量分析

| 场景 | 估算并发量 | 主要压力点 |
|---|---|---|
| 平时使用 | 500~1,000 并发 | 论文查看、状态查询 |
| 提交高峰（截止日前2天）| 3,000~5,000 并发 | 论文提交、文件上传 |
| 最大并发（全校同时在线）| 10,000 并发 | 混合操作 |
| 答辩峰值 | 50~200 路 RTC 流 | 视频流处理 |

#### 6.1.2 性能优化策略

**数据库层优化**：
- 读写分离：80% 读请求路由至从库
- 热点数据 Redis 缓存（论文状态、用户权限、统计数据）
- 慢查询监控：`slow_query_log` 开启，超过 100ms 的查询自动告警
- 核心表索引优化：`(school_id, batch_id, status)` 联合索引

**应用层优化**：
- 论文列表接口：分页查询 + 游标分页（深翻页场景）
- 批量操作：`INSERT INTO ... VALUES (...),(...)` 批量写，单批 500 条
- 异步化：文件处理、通知推送、AI 分析全部异步，不阻塞用户操作
- 连接池：Druid 连接池，初始连接 10，最大 100，按需扩展

**文件上传优化**：
- 前端直传 OSS（预签名 URL），不经过业务服务器，彻底卸载文件传输压力
- 大文件分片上传（> 10MB 启用分片，每片 5MB），支持断点续传
- 图片自动压缩（OSS 图片处理服务，上传后自动缩略）

**网络层优化**：
- CDN 加速静态资源（JS/CSS/图片），命中率 > 95%
- HTTP/2 多路复用，减少连接开销
- Gzip/Brotli 压缩，减少传输体积 60~70%

#### 6.1.3 限流熔断设计

使用 **Sentinel** 进行多维度流控：

| 接口类型 | 限流规则 | 熔断规则 |
|---|---|---|
| 登录接口 | 同 IP 每分钟 20 次 | 错误率 > 50% 熔断 30s |
| 论文提交 | 同用户每分钟 5 次 | — |
| AI 类接口 | 全局 QPS ≤ 100 | 响应时间 > 15s 熔断 60s |
| 普通查询 | 单服务实例 QPS ≤ 1000 | 错误率 > 20% 熔断 20s |
| 文件上传 | 全局并发 ≤ 500 | — |

### 6.3 安全设计

#### 6.3.1 认证与授权安全

### 7.1 分布式会话与 Token 管理

```java
// Sa-Token 多端登录配置
@Configuration
public class SaTokenConfig {
    @Bean
    public SaTokenConfig getSaTokenConfigPrimary() {
        SaTokenConfig config = new SaTokenConfig();
        config.setTokenName("Authorization");
        config.setTimeout(60 * 60 * 24 * 7);    // 7天有效期
        config.setActivityTimeout(60 * 60 * 2);  // 2小时无操作自动过期
        config.setIsConcurrent(false);            // 同账号不允许多端同时登录
        config.setIsShare(false);
        config.setTokenStyle("uuid");
        return config;
    }
}

// 登录（手机号+验证码）
public String loginByPhone(String phone, String code) {
    // 校验验证码
    String cacheCode = redisTemplate.opsForValue().get("sms:" + phone);
    if (!code.equals(cacheCode)) throw new BusinessException("验证码错误");
    // 查询用户
    User user = userMapper.selectByPhone(phone);
```

```java
/**
 * 论文状态流转服务
 */
@Service
public class PaperFlowService {

    /**
     * 学生提交论文节点
     */
    @Transactional
    public void submitNode(Long paperId, Long studentId, String nodeType, MultipartFile file) {
        // 1. 获取当前批次流程配置
        BatchFlowConfig nodeConfig = flowConfigMapper.selectByBatchAndNode(
            paper.getBatchId(), nodeType);
        if (nodeConfig == null || !nodeConfig.isEnabled()) {
            throw new BusinessException("当前节点未开启");
        }
        // 2. 校验节点顺序（强制顺序场景）
        if (nodeConfig.isRequired()) {
            validatePreviousNodeCompleted(paperId, nodeConfig.getSortOrder());
        }
        // 3. 校验时间窗口
        LocalDateTime now = LocalDateTime.now();
        if (now.isBefore(nodeConfig.getStartTime()) || now.isAfter(nodeConfig.getEndTime())) {
            // 检查是否有逾期提交授权
            if (!hasDeadlineExtension(paperId, nodeType)) {
                throw new BusinessException("不在提交时间范围内");
            }
        }
        // 4. 保存提交记录
        PaperSubmitRecord record = buildSubmitRecord(paperId, studentId, nodeType, file);
        submitRecordMapper.insert(record);
        // 5. 更新论文节点状态
        updatePaperNodeStatus(paperId, nodeType, PaperStatus.SUBMITTED);
        // 6. 发布提交事件（触发通知、AI评议等）
        eventPublisher.publish(new PaperSubmitEvent(paperId, nodeType, studentId));
    }

    /**
     * 教师审核论文节点
     */
    @Transactional
    public void reviewNode(Long paperId, Long teacherId, String nodeType,
                           ReviewDecision decision, String comment, Integer score) {
        // 1. 校验教师对该论文该节点的审核权限
        validateReviewPermission(paperId, teacherId, nodeType);
        // 2. 检查评语最低字数
        BatchFlowConfig config = getNodeConfig(paperId, nodeType);
        if (comment.length() < config.getMinCommentLength()) {
            throw new BusinessException("评语不得少于" + config.getMinCommentLength() + "字");
        }
        // 3. 保存审核记录（含批注和评分）
        saveReviewRecord(paperId, teacherId, nodeType, decision, comment, score);
        // 4. 状态流转
        PaperStatus nextStatus = decision == APPROVED ? PaperStatus.APPROVED : PaperStatus.REJECTED;
        updatePaperNodeStatus(paperId, nodeType, nextStatus);
        // 5. 若通过，检查是否需要流转至下一级导师
        if (decision == APPROVED) {
            advanceToNextTeacherLevel(paperId, nodeType, teacherId);
        }
        // 6. 若末级通过，流转至下一节点
        eventPublisher.publish(new PaperReviewEvent(paperId, nodeType, decision));
    }
}
```

### 7.3 选题去重分布式锁实现

```java
/**
 * 选题选择（分布式锁防止并发抢选同一题目）
 */
@Service
public class TopicSelectService {

    @Resource
    private RedissonClient redissonClient;

    public boolean selectTopic(Long studentId, String topicTitle, Long batchId) {
        // 计算选题哈希（按批次+选题标题）
        String topicHash = DigestUtils.md5Hex(batchId + ":" + topicTitle.trim());
        String lockKey = "topic:lock:" + topicHash;

        RLock lock = redissonClient.getLock(lockKey);
        try {
            // 尝试抢占（等待 0 秒，锁定 30 秒）
            boolean locked = lock.tryLock(0, 30, TimeUnit.SECONDS);
            if (!locked) {
                // 该选题已被其他学生选走
                throw new BusinessException("该选题已被其他同学选择，请重新选择");
            }
            // 双重校验（防止锁刚释放时的并发）
            if (topicMapper.existsSelectedTopic(batchId, topicTitle)) {
                throw new BusinessException("该选题已被其他同学选择，请重新选择");
            }
            // 写入数据库
            topicMapper.insert(buildTopicRecord(studentId, topicTitle, batchId));
            return true;
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException("系统繁忙，请稍后重试");
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }
}
```

```java
/**
 * 按学校模板导出标准论文 DOCX

@Service
public class PaperExportService {

    public byte[] exportToDocx(Long paperId, Long templateId) {
        // 1. 获取论文数据
        PaperExportDTO paper = paperMapper.selectExportData(paperId);
        // 2. 获取学校模板文件（从 MinIO）
        byte[] templateBytes = minioClient.getObject(paper.getTemplateFileUrl());
        // 3. 使用 Apache POI 填充模板
        try (XWPFDocument doc = new XWPFDocument(new ByteArrayInputStream(templateBytes))) {
            // 填充封面信息
            fillCoverPage(doc, paper);
            // 填充摘要
            fillAbstract(doc, paper);
            // 填充正文（按大纲树递归渲染章节）
            fillBody(doc, paper.getOutlineNodes());
            // 填充参考文献
            fillReferences(doc, paper.getReferences());
            // 输出为字节数组
            ByteArrayOutputStream out = new ByteArrayOutputStream();
            doc.write(out);
            return out.toByteArray();
        }
    }

    private void fillBody(XWPFDocument doc, List<OutlineNode> nodes) {
        for (OutlineNode node : nodes) {
            // 添加标题段落（按层级应用 Heading 样式）
            XWPFParagraph heading = doc.createParagraph();
            heading.setStyle("Heading" + node.getLevel());
            heading.createRun().setText(node.getTitle());
            // 添加内容段落
            if (StringUtils.hasText(node.getContent())) {
                renderRichContent(doc, node.getContent());
            }
            // 递归处理子节点
            if (!CollectionUtils.isEmpty(node.getChildren())) {
                fillBody(doc, node.getChildren());
            }
        }
    }
}
```

```java
@Service
public class AiServiceFacade {

    public String generateText(String systemPrompt, String userPrompt) {

        return Retry.decorateSupplier(
            Retry.of("ai-retry", RetryConfig.custom()
                .maxAttempts(3)
                .waitDuration(Duration.ofSeconds(2))
                .retryOnException(e -> e instanceof AiTimeoutException)
                .build()),
            () -> client.chat(systemPrompt, userPrompt)
        ).get();
    }

     * 流式输出（用于大纲推荐等长文本生成，实时显示给用户）

    public Flux<String> generateTextStream(String systemPrompt, String userPrompt) {
        return getClient(aiProvider).chatStream(systemPrompt, userPrompt);
    }

    private AiClient getClient(String provider) {
        return switch (provider) {
            case "wenxin" -> wenxinClient;
            case "tongyi" -> tongyiClient;
            default -> openAiClient;
        };
    }
```
